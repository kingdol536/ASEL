- 상태: **사전 고정** — 2026-11-11, 티켓 #32. 코어 동결(#35) 과 새 환경 이식(#37 환경 B, #41 환경 C) **전에** 커밋한다.
- 스크립트: `experiments/configs/portability_metrics.py <동결 커밋> <이식 완료 커밋> --env <이름>`
- 관련: docs/07 §7 (첫 이식성 실험), R-05, 공통 언어 v0 (`docs/11-COMMON-LANGUAGE.md`)

## 무엇을 재나

새 산업 환경을 붙일 때 **무엇을 얼마나 고쳐야 했는가**. 결과를 본 뒤 유리한 지표를 고르지 않도록 아래 7개를 미리 고정한다.

| 지표 | 정의 | 좋은 방향 |
|---|---|---|
| `core_diff_lines` | `src/asel/core/` 추가+삭제 줄 수 | 0 |
| `engine_diff_lines` | 코어 밖 공용 엔진(정책·평가·입출력·실행기) 추가+삭제 줄 수 | 작게 |
| `adapter_lines` | `src/asel/domains/` 추가+삭제 줄 수 (도메인 전용 코드) | 작게 |
| `config_lines` | `scenarios/` 추가 줄 수 (설정만으로 표현한 양) | — |
| `public_interface_changes` | 코어 공개 이름(최상위 이름, 데이터 클래스 필드, 행동·사건 이름)의 추가+삭제 수 | 0 |
| `new_concepts` | 공통 언어 목록의 개념·값·행동·사건 추가+삭제 수 | 작게 (추가는 기록하고 이유를 적는다) |
| `config_only_ratio` | `config / (config + adapter + engine + core)` | 1 에 가깝게 |

## 해석 규칙 (사전 고정)

- **환경 B (조립 라인)** 는 공통 언어 v0 이후 코어 설계 단계에서 존재를 알았던 환경이다. B 의 수치는 '설계 참고 환경'으로 따로 보고하고 이식성의 증거로 쓰지 않는다.
- **환경 C** 는 코어 동결 커밋 **이후에** 설계를 시작한다. C 의 수치를 이식성의 주된 증거로 쓴다. 동결 커밋 시각 < C 설계 시작 커밋 시각을 보고서에 적는다.
- 줄 수는 코드 품질이나 작업량의 대리 지표일 뿐이다. 수치와 함께 **바뀐 이유**(어떤 개념이 모자랐나)를 반드시 적는다.
- 공백·주석 변경도 줄 수에 포함된다(단순하고 조작하기 어려운 정의를 택함). 대량 서식 변경은 이식 작업과 섞지 않는다.
- 두 환경 결과를 '모든 산업 범용성'으로 해석하지 않는다 (docs/07 §7).
