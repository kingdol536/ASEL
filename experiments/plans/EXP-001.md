## 1. 질문

같은 부분 관측과 같은 행동 계약(제안 → 검증 → 적용) 아래에서, **Claude 정책이 세계를 안전하게 운영할 수 있는가**,
그리고 그 결과와 비용은 고정 규칙(FIFO)·규칙 기준선과 비교해 **어떤 조건에서 어떻게 다른가**?

이 실험은 M3 게이트용 **통합·실행 가능성 실험**이다. 성능 우열을 증명하는 실험이 아니다 (§7 한계 참조).

## 2. 가설과 반증 조건

| ID | 가설 | 반증 조건 |
|---|---|---|
| H1 (안전 경계) | Claude 정책의 제안이 검증기를 거치는 한, 불변조건 위반과 숨겨진 값 접근은 0건이다 | 위반 1건 이상, 또는 관측·프롬프트에 비공개 필드가 들어간 기록 1건 이상 |
| H2 (유효 제안) | Claude 정책의 무효 제안 비율은 수요 급증·고장 시나리오에서 정상 시나리오보다 높다 (상태가 복잡할수록 실수가 는다) | 시나리오 간 차이의 대응 신뢰구간이 0 을 포함하거나 반대 방향 |
| H3 (운영 결과) | 정책 차이가 주문 처리 시간 분포에 나타나는 것은 **수요 급증 구간**에서만이고, 정상 시나리오에서는 차이가 무시할 만하다 | 정상 시나리오에서도 대응 차이의 신뢰구간이 0 을 벗어남, 또는 급증에서도 0 을 포함 |
| H4 (비용) | Claude 정책의 실행당 비용·지연은 사건 기반 호출로 상한(§5) 안에 든다 | 파일럿에서 실행당 비용이 상한을 넘음 |

H2·H3 의 방향은 사전 예상이며, 반대 결과도 그대로 보고한다.

## 3. 비교 정책 (모두 같은 관측·행동 계약)

| ID | 정책 | 정보 | 비고 |
|---|---|---|---|
| P-FIFO | 준비 순서대로 첫 가용 셀 | 관측 투영(#9)만 | 현재 기본값 |
| P-RULE | 규칙 기준선: **주문 나이 우선** (가장 오래된 주문의 작업 먼저, 포장 단계 우선) | 동일 | #10. 실제 처리 시간은 숨겨져 있으므로 쓸 수 없다 — **결정 필요**: 이 규칙으로 할지 |
| P-CLAUDE-H | Claude Haiku 5.5 | 동일 관측을 JSON 으로 + 허용 행동 목록 | #11/#13 |
| P-CLAUDE-S | Claude Sonnet 5.5 (선택) | 동일 | **결정 필요**: 두 번째 모델 팔을 둘지 (예산 영향) |

공정성 조건:
- 모든 정책은 같은 관측 투영을 받는다 (실제 처리 시간·미래 도착·고장 원인 없음).
- 결정 시점이 같다: 대기 작업이 있고 가용 셀이 생기는 사건마다 한 번.
- Claude 정책은 결정 시점마다 최대 1회 호출하고, 실패·타임아웃이면 P-FIFO 로 대체한다. 대체 비율을 결과로 보고한다.
- 규칙 정책의 계산 비용은 0 으로 두고, Claude 의 호출 예산은 **실험 변수**로 기록한다.

## 4. 지표 후보 (결정 필요: 채택할 지표 선택)

| 지표 | 단위 | 수집 경로 | 정답 산정 | 오용 위험 |
|---|---|---|---|---|
| 무효 제안 비율 | 거절 수 / 제안 수 | 공개 로그 `ActionProposed`/`ActionRejected` | 검증기 판정 | 아무것도 제안하지 않으면 0% → 제안 수·대기 작업과 같이 본다 |
| 주문 처리 시간 | s (도착 → 포장 완료) | 공개 로그 시각 | 평가기 | 끝나지 않은 주문은 빠진다 → **완료율과 같이** 보고, 미완료는 중도절단으로 표시 |
| 처리 시간 P95 | s | 위와 같음 | 평가기 | 표본이 작으면 불안정 → 시드별 분포를 함께 공개 |
| 완료 주문 수 | 건 / 3600s | 공개 로그 | 평가기 | 수요가 같으므로 처리 시간과 중복될 수 있음 |
| 종료 시점 대기 작업 | 건 | 공개 로그 | 평가기 | 종료 시각 하나에 민감 |
| 결정 비용 | 호출 수·입출력 토큰·지연(ms)·비용($)/실행 | 정책 어댑터 기록 → manifest | 어댑터 | 캐시 적중을 실제 호출로 세면 안 됨 |
| 대체 비율 | 대체 결정 / 전체 결정 | 어댑터 기록 | 어댑터 | 높으면 Claude 결과가 사실상 FIFO 결과 |

평가기(#12)는 비공개 로그를 읽을 수 있지만, 위 지표는 모두 공개 로그만으로 계산된다 (정답 사용 없음).
비공개 로그는 "정책이 숨겨진 값을 보지 않았음" 검증(H1)에만 쓴다.

## 5. 시나리오·시드·예산

- 시나리오: `warehouse-small-a`, `warehouse-surge-a`, `warehouse-fault-a`.
- **개발용 시드 0~9**: 프롬프트·규칙 조정에만 사용.
- **평가용 시드 100~129** (30개, 임시): 개발 중 보지 않는다. 파일럿 분산을 보고 표본 수를 다시 정한다.
- **보류(held-out) 시나리오**: 다른 셀(피킹 셀)이 고장 나는 변형 1개를 평가 직전에 만든다. 개발 중 사용하지 않는다.
- 예산: **총 상한 $55** (프로모션 크레딧, 2026-11-19 만료). 상한이지 소진 목표가 아니다. 남으면 소멸을 감수한다.
  - 파일럿: Haiku, 시나리오별 개발 시드 2개 = 6회 → 실행당 비용·지연 측정.
  - 본 실험 예산은 파일럿 결과로 계산해 이 문서에 추가하고, 그 뒤에 실행한다.
  - 코드 상한(예산 가드): 누적 비용 또는 호출 수가 상한에 닿으면 즉시 호출 중단 → 남은 결정은 대체 정책.

## 6. 분석 계획 (사전 고정)

- 같은 시드는 같은 수요·처리 시간이므로 **정책 간 대응 차이**를 시드별로 계산한다.
- 대응 차이의 평균과 부트스트랩 95% 신뢰구간 (재표본 10,000회, 시드 고정).
- 평균만이 아니라 시드별 분포·최악 사례를 같이 공개한다. 여러 지표를 하나의 점수로 합치지 않는다.
- 결과를 본 뒤 지표나 시드를 바꾸면 **탐색적 분석**으로 표시한다.

## 7. 한계 (미리 밝힘)

- **환경 A 의 결정 공간이 좁다.** 셀 역할이 고정이고 포장 셀이 1개라, 정책이 바꿀 수 있는 것은 사실상 '어떤 대기 작업을 먼저' 뿐이다. 처리량 차이는 작을 가능성이 높다. 정책 차이가 크게 나는 실험은 구조 변경이 들어오는 M4(EXP-002 예정)의 몫이다.
- 고장 의미가 단순하다 (결정 0003).
- LLM 응답은 비결정적이다. 재현은 녹화된 응답(캐시)으로만 보장한다.
- 가상 시나리오이며 현실 물류 성능을 뜻하지 않는다.

## 8. 종료 규칙

- 예산 가드 발동 시 중단하고 그때까지의 결과를 보고한다.
- 파일럿에서 무효 제안 비율이 50% 를 넘으면 본 실험을 하지 않고 인터페이스(관측 형식·프롬프트)를 고친다. 이 파일럿은 결과에 포함하지 않고 기록만 남긴다.
