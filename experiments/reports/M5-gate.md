### 3.2 재현성

- **기록된 실험 1,080회(EXP-001 270 + EXP-002 810) 사건 로그 바이트 동일** — M5 의 모든 변경 후 `verify_reproduction.py` 로 확인. Claude 실행은 캐시 재생, API 호출 0.
- 이 점검 중 **기존 회귀를 발견해 고쳤다**: M4 에서 추가된 `reconfigurable` 항목이 0.1/0.2 시나리오의 설정 해시(→ run_id → 사건 로그)를 바꿔 EXP-001 바이트 재현이 M4 병합 이후 깨져 있었다. 정규 형식을 선언된 스키마 버전에 맞춰 복원하고 회귀 테스트를 넣었다.
- 새 항목(흐름·혼류·목표·공간)은 쓰지 않는 시나리오의 관측·사건·최종 상태 형식을 바꾸지 않는다 (테스트로 확인).

### 3.3 AI 즉시 연결

- Claude 정책을 B·C 에 **소스 코드 변경 0줄**로 연결 (정책 규약·관측 투영이 그대로 동작). 산업 중립 프롬프트 `v2-neutral`, 기존 녹화는 `v1-warehouse` 로 보존.
- 주의: 기본 프롬프트는 EXP-001 재생을 위해 `v1-warehouse` 다. B·C 에서는 `ASEL_LLM_PROMPT=v2-neutral` 을 **명시해야** 한다 (EXP-003 계획서에 고정할 항목).
- 안전 경계: 숨겨진 처리 시간이 프롬프트에 없음, 목표는 전달되지만 채점값은 전달되지 않음, 무효 제안은 거절. **실제 API 호출은 하지 않았다** (EXP-003 승인 전).

### 3.4 3D 공간 제약: 2D 에서 유효한 구조 변경이 3D 에서 불가능 (탐색적, 개발 시드 0~9)

| 시나리오 | P0 처리 시간 평균 | P1 처리 시간 평균 | P1 전환 횟수 |
|---|---|---|---|
| B (2D, 공간 정보 없음) | 378.2 s | **338.2 s** | 0.8 |
| B-3D (press-2 천장 3.2 m, press-A 3.8 m 필요) | 378.2 s | **378.2 s** | 0 |

같은 정책·같은 시드에서 2D 에서는 공용 프레스를 press-A 로 돌려 처리 시간을 줄이지만, 3D 에서는 높이 제약 때문에 그 전환이 불가능해 고정 구조와 같아진다.
docs/05 §8 의 합격 기준("3D 에서 추가된 제약 때문에 2D 의 가정이 깨질 수 있음을 재현하고, 행동 허용/거절로 연결")을 화면 없이 충족했다. 그래픽 시각화는 결정 0007 에 따라 후순위.

### 3.5 이식된 정책의 실패 사례 (탐색적, 개발 시드 0~9)

| 환경 C (IT 서비스) | P0 | P1 | P2 |
|---|---|---|---|
| 시간 초과로 취소된 요청 (실행당 평균) | 24.5 | **104.1** | **166.6** |
| 완료 요청 처리 시간 평균 | 21.5 s | 24.4 s | 22.8 s |

M4 에서 만든 구조 정책(P1/P2)은 **대기열 압력만 보고 요청 기한을 모른다**. C 에서 배치 작업 대기가 길어지자 앱 서버를 배치 워커로 돌렸고, 그 결과 앱 용량이 줄어 시간 초과가 4~7배로 늘었다.
물류·조립에서 이득이던 정책이 다른 산업 구조에서는 해가 되는 사례다 — **엔진(표현)은 이식됐지만 정책(판단)은 그대로 이식되지 않는다**. 원자료: [dev_seed_exploration.txt](assets/M5/dev_seed_exploration.txt)

### 3.6 목표 변경

- 목표는 공개 사건(`ObjectiveChanged`)과 관측으로 전달되고, 채점식(시간당 완료, 우선 흐름 처리 시간)은 평가기에만 있다.
- 목표를 읽는 기준 정책(objective-aware)이 '우선 흐름' 목표에서 대상 흐름을 먼저 처리하는 것을 테스트로 확인했다 (기능 확인).
- 실험에 쓸 목표와 채점식은 R-07(미결정)이므로 계획서 승인 대상이다.

## 4. 남은 위험

- **M4 원자료 유실:** EXP-002 원본 로그가 M4 작업 폴더 삭제 때 지워졌다. 같은 코드로 다시 만들어 평가표 810행×29열이 동일함을 확인했다. 원자료는 git 밖(`experiments/batches`)에만 있으므로 보관 방법(압축 첨부 등)이 필요하다.
- 공통 언어는 3개 환경에서 키운 v0 다. 재고·버퍼·운반·재작업(R-16), 재시도·조건 분기는 표현하지 못한다.
- 시간 초과는 진행 중 작업을 끝까지 처리한다 (자원 회계 단순화). 실제 서비스의 요청 중단과 다르다.
- 3D 는 정적 배치·높이 제약 하나뿐이다. 이동·충돌·물리는 없다.
- §3.4·§3.5 는 개발 시드 탐색이다. 확증하려면 계획서(EXP-003 후보)가 필요하다.
- 관측의 `order` 키는 '작업 묶음 id' 를 뜻하는 예전 이름이다 (재현성 때문에 유지).
