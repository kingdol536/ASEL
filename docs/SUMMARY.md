# ASEL 한 장 요약 (2026-11-11 기준)

> 모든 수치는 기능 검증용 **가상 시나리오**의 실제 실행 측정값이다. 현실 공정·서비스 성능을 뜻하지 않는다.

## 연구 질문

서로 다른 산업 현장을 **하나의 공통 언어**(개념·관계·행동·사건)로 조립해 표현할 수 있는가?
그 위에서 AI(Claude)가 작업 배정과 **시스템 구조 변경**(셀 역할 전환)을 판단하게 하면, 어디서 통하고 어디서 실패하는가?

## 시험 환경 (모두 같은 엔진, 설정 파일로 표현)

| 환경 | 특징 | 구조 변경 |
|---|---|---|
| A 물류 창고 | 주문 흐름, 수요 급증, 고장 | 셀 역할 전환 (비우기 → 전환 → 새 역할) |
| B 조립 라인 | 공정 순서(DAG), 두 제품 혼류, 3D 천장 높이 제약판 | 프레스 셀 press-A ↔ press-B (셋업 90 s) |
| C IT 서비스 | 대화형 요청(시간 제한 10~15 s) + 배치 작업, 캐시 적중·실패 흐름 | 인스턴스 app ↔ worker (60 s). 공통 언어를 고정한 **뒤** 설계 |

## 방법

- 정책은 환경을 직접 바꾸지 못한다: **제안 → 검증 → 적용 → 사건** 계약. 숨겨진 참값(실제 처리 시간·고장 원인)은 비공개 로그에만 있고 독립 평가기만 본다.
- 같은 시드 → 같은 사건 로그 (바이트 단위, Windows·Ubuntu 교차 검사). Claude 응답은 캐시해 재생하면 API 호출 0.
- 실험마다 계획서를 실행 전에 커밋·푸시해 고정(사전 등록). 같은 시드끼리 대응 차이, 부트스트랩 95% CI.

## 결과

| 실험 | 결과 | 가설 |
|---|---|---|
| EXP-001 (A, 270회) | Claude 배정: 안전 경계 위반·숨겨진 값 누출 0, 무효 제안 0%. 처리 시간은 FIFO 와 1% 미만 차이 | 지지 2 · 반증 2 |
| EXP-002 (A, 810회, **잠정**) | 셀 역할 전환은 전환이 싸고 급증이 클수록 이득(급증 2배 −105 s). 전환이 비쌀수록 이득이 줄지만 뒤집힘은 없음. 전환이 병목을 다른 곳으로 옮김 | 지지 3 · 부분 지지 1 |
| M5 이식성 | B: 엔진 코어 수정 0줄. C: 코어 23줄(행동 1개 추가, 기존 변경 0). 물류용 구조 정책을 C 에 옮기면 시간 초과가 4~7배. 3D 천장 제약: 2D 에서 되던 전환이 막혀 처리 시간 338 → 378 s | 탐색적 |
| EXP-003 (B·C, 415회) | **Claude 구조 제어:** B 처리 시간 −16% (30/30 시드, 규칙 정책보다 좋음). C 취소 약 7배 — 역할을 되돌리며 처리 공백을 만듦. **Claude 배정:** 유효·안전, FIFO 대비 비열등이나 무료 규칙보다 낫지 않음 | 지지 5 · 반증 2 · 판정 불가 1 |

재현: 기록된 실험 1,495회를 실행 목록만으로 다시 돌려 사건 로그 SHA-256 을 대조할 수 있다 (`reproduce.py`).

## 결론

1. **표현의 이식은 된다.** 공통 언어를 고정한 뒤 설계한 IT 서비스도 코어 행동 1개 추가로 표현했다.
2. **판단의 이식은 환경에 따라 정반대다.** 같은 AI 구조 제어가 조립 라인에서는 규칙보다 낫고, IT 서비스에서는 가장 나쁘다. 실패 기전은 같은 정보를 받은 규칙 정책과 같다(관측에 시간 제한이 없음 — **가설**).
3. **구조 변경은 병목을 옮긴다.** 해결책이 다음 제약을 만든다는 장기 질문(병목의 공진화)의 첫 증거다.
4. 사건마다 AI 를 부르는 배정은 비용에 맞는 이득이 없었다. 판단 빈도를 제한한 구조 제어는 비용이 1~20% 수준이다.

## 한계

- 환경 3개, 재구성 가능한 셀 각 1개, 프롬프트 각 하나. 3개 환경 결과를 모든 산업의 범용성으로 해석하지 않는다.
- 3D 는 정적 배치·천장 높이 제약을 엔진에서 검증하고, 그 결과를 3D 화면으로 재생하는 수준이다(물리 엔진·이동체 없음, 결정 0007).
- 시뮬레이션 안 AI 의 최종 역할·권한 구성과 최종 평가 지표는 **미결정**이다. M4 결과와 결정 0005·0006 은 사용자 승인 전 잠정이다.

## 다음 과제

- 시간 제한을 고려하는 구조 정책 (규칙 기반) — IT 서비스 실패를 직접 다룬다
