## 1. 성공의 정의

12주가 끝났을 때 **독립 실행 가능한 제한된 연구 결과물**이 있어야 한다.

- 공통 환경 모델과 AI/정책 연결 계약이 실제로 작동한다.
- 2D 단위 실험과 headless 반복·재현이 가능하다.
- 구조적 변경을 한 가지 이상 수행하고 영향·부작용을 실험한다.
- 숨겨진 사실에 대한 정보 유출 없이 AI/정책 실행을 평가할 수 있다.
- 한 가지 **3D 고유 공간 제약**을 엔진에서 검증한다 (화면 없이, 결정 0007). 3D 그래픽 장면은 후순위.
- 공개 가능한 코드·실험 설정·결과·한계·데모를 준비한다.

효율/이식성/통제성 등의 최종 주지표와 AI 역할 수는 **아직 미결정**. 완료 기준은 '정해진 결과 수치 달성'보다 **명세된 가설을 재현 가능하게 시험**하는 데 둔다.

## 2. 12주 단계별 작업

| 기간 | 난도(잠정) | 구현·학습 | 종료 게이트(실증 자료) |
|---|---|---|---|
| **W1–2** | 중 | 프로젝트 스캐폴드, 공통 상태/행동 스키마, 작은 환경 A, 1차 연구 질문·시험 규약 | 설정·시드로 작업 흐름 재현, 핵심 불변조건 테스트 |

| **W5–6** | 중~상 | 정책 인터페이스, 정답 격리, 모의/기준선 정책, AI 모델 어댑터 최소 연동 | 허가된 관측만 전달; 무효 행동 거절; 동일 시나리오 비교 |

**단계는 서로 겹칠 수 있음.** 렌더러 시험 장면은 W3–4부터 병행하고 W11에 처음 착수하지 않는다. 구현이 예상보다 늦으면 3D 장면 규모/정밀도를 줄이되 연구 검증과 제출물을 우선한다.

## 3. 세부 마일스톤

### M1 — 상태가 신뢰 가능한 세계 (W2)

- 구현: 상태/행동/시간/작업 생명주기.
- 증거: `scenario.yaml`, 단위 테스트, 동일 시드 replay.
- 실패 기준: 작업·자원 상태가 쉽게 불일치하면 AI 개발로 진행하지 않는다.

### M2 — 관찰 가능한 세계 (W4)

- 구현: headless batch runner + 2D 관계/공간 표시 + 이벤트 저장.
- 증거: 정상·수요 급변·자원 장애의 작은 테스트 세트.
- 실패 기준: 렌더링 유무가 논리 이벤트를 변경한다면 분리 설계 수정.

### M3 — 제어·평가 분리 (W6)

- 구현: PolicyAdapter/AgentAdapter, ActionValidator, 독립 평가기.
- 증거: 비공개 진실값 노출 테스트, 정책 제안 거절과 회복 경로.
- 실패 기준: 모델 출력이 임의로 세계를 직접 조작한다면 인터페이스 수정.

### M4 — 구조 변경과 병목 연쇄 (W8)

- 구현: 전환 가능한 모듈/경로, 변경 비용·중단시간, 비교 정책.
- 증거: 전후 상태·새로운 제약 후보·악화 사례. **긍정적인 향상 수치를 강요하지 않는다**.
- 실패 기준: 변경 비용이 무시돼 정책이 무한히 재구성한다면 세계 모델 검토.

### M5 — 복수 조건 실험 (W10)

- 구현: 목표 변환 또는 구조 B, 역할 구성 비교 및 반복 평가.
- 증거: 코어 수정량, 재현성, 비교 정책 예산, 실패 조건.
- 실패 기준: 다른 환경 결과를 보고 나서 조용히 정책을 맞춘 경우 holdout 평가 재설계.

### M6 — 통합 포트폴리오 (W12)

- 구현: 3D 공간 제약 하나의 엔진 검증(결정 0007), 재실행 스크립트, 보고서. 3D 그래픽 영상은 선택.
- 증거: 설치·재현 방법, 결정/오류/한계 기록, 샘플 결과.
- 실패 기준: 결과가 예쁜 영상만 있고 근거 데이터/코드가 없는 경우 미완료.

## 4. 우선순위와 절제 기준

### 반드시 남길 것

1. 세계·상태 모델의 정확성.
2. 액션/정보 경계와 독립 평가.
3. 명확한 구조 변경 1종과 공정한 비교 실험.
4. 데이터 수집 및 재현성.
5. 3D의 실제 공간·물리 제약을 다루는 최소 통합 사례.

### 먼저 줄일 것

고충실도 그래픽 → 환경에 있는 객체 수 → AI 역할 수 → 두 번째 산업 환경의 규모 → 고급 최적화 기법 순으로 줄인다. **역할의 가변성**은 유지하되 실제 가동 수를 줄이는 것은 가능하다.

## 5. 포트폴리오 패키지

- 공개 저장소 및 주요 기능 테스트.
- 주요 아키텍처 결정(ADR), AI 사용 범위와 본인 판단 근거.
- 실험 프로토콜, 설정·시드·정량 결과, 반례/한계.
- 2D 분석 장면, 3D 통합 시연, 구조 변경 사건 타임라인.
- 한 장 요약: 연구 질문 / 시험 환경 / 가설 / 결과 / 결론 / 다음 과제.
- 가능하다면 외부 개발자에게 실행해 보게 하고 피드백을 기록.

## 6. 후속 5~12개월 연구(12주 이후)

| 단계 | 주제 | 결과의 조건 |
|---|---|---|
| E1 | 목표 변경에 따른 구조 진화, 다목적/제약 전환 | 목표가 바뀔 때 구조 재사용·변경 비용·제약 준수의 경계 분석 |
| E2 | 3D 통합 고도화, 물리 모델 결합 | 물리 모델의 가정/단위/시간 스케일 및 오류 추적 검증 |
| E3 | 정보 복잡도·모델 정밀도 선택 | 계산 비용 대비 진단 품질·정밀도 전환 비용 비교 |
| E4 | 위기 대응 및 방어적 복원력 | 재난·고장·악의적 장애 조건에서 필수 기능 유지/복구 평가 |
| E5 | 역할/권한/조직의 동적 재구성 | 통신비용·조정 안정성·정책 충돌의 병목 이동 검증 |
| E6 | 다른 산업/IT 시스템 이식 | 코어 재사용 범위·새 어댑터 비용·실패 사례 공개 |

순서와 범위는 연구 결과와 취업 이후 시간에 맞춰 조정. 모든 항목 완료가 성공의 조건은 아니다.

## 7. 프로젝트와 취업 실행의 병행

- 12주 완성 이전에도 중간 데모와 연구 기록 공개 가능.
- 학력·경력 부족의 보완은 화려한 비전보다 **내가 직접 설명하고 재현할 수 있는 기술적 증거**로 달성.
- 생계 확보 목표와 충돌하면 실행 시간을 조정하고 마일스톤 범위를 축소. 취업 결과는 기술 실험의 성과와 구분해서 평가.
