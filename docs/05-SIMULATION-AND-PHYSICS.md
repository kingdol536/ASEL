# 05. 시뮬레이션·물리 모델·3D 표현

## 1. 핵심 설계 원칙: 시뮬레이션은 렌더러가 아니다

프로젝트의 목적은 **산업 시스템의 구성·상태·제약과 AI의 운영·재구성 행동을 시험하고, 그 결과와 후속 병목을 검증하는 것**이다. 3D 표현은 중요한 통합 검증 수단이지만, 화면의 사실성이 곧 모델의 공학적 타당성을 뜻하지 않는다.

- **논리 시뮬레이션 코어:** 작업·자원·관계·구조 변경·이벤트·상태 전이·시뮬레이션 시간을 책임진다.
- **물리 계산 어댑터:** 실제로 필요한 경우 위치·속도·접촉·충돌·동력·열 같은 물리량을 계산한다. 일반적으로 게임 엔진 내장 물리와 전문 물리 솔버는 목적과 정확도 요구가 다르다.
- **3D 렌더러·조작 인터페이스:** 상태와 공간 구성, 실험 결과를 시각화한다. 원칙적으로 표시만을 위해 정답인 세계 상태를 새로 계산하지 않는다.
- **AI/정책 시스템:** 허가된 관측으로 행동·설계 변경을 제안한다. 실행 권위나 평가 참값을 직접 소유하지 않는다.
- **독립 평가기:** 실험의 비공개 참값, 상태 기록, 시나리오를 활용해 별도로 검증한다.

```text
[Scenario / Experiment Runner: seed, workload, hidden conditions]
                         |
                  [World State + Clock]
                         |
             [Simulation Coordinator]
              /          |          \
     [Logical Core] [Physics Adapter] [Model Registry]
              \          |          /
               [Validated State / Events]
                         | \
                 [Agent Observation] --> [Policy/Agent] --> [Action Validator]
                         |                                |
                 [Independent Evaluator]            [Coordinator]
                         |
                  [Replay / State Stream]
                         |
                   [2D / 3D Viewer]
```

도식은 **논리적 책임**을 나타내며 프로세스 분할·네트워크 구성의 확정안은 아니다. 평가기 비공개 데이터는 내부 AI로 전달하지 않는다.

## 2. 단계 구분: Headless → 2D 단위 검증 → 3D 통합 검증

| 방식 | 주목적 | 물리·공간 수준 | 12주 범위 |
|---|---|---|---|
| **Headless** | 반복 실험·통계·회귀 테스트 | 논리 상태/필요한 수치만 계산 | **필수** |
| **2D 기능 실험** | 관계·경로·상태·AI 행동·제약을 빠르게 검사 | 평면 배치, 추상 경로, 제한된 충돌 규칙 | **필수** |
| **3D 최소 통합** | 개별 기능의 상호작용과 3D 고유 제약 확인 | 높이·점유·충돌·수직 이동 등 최소 1개 이상 실제 제약 | **12주 목표** |
| **3D 고충실도/다중 물리** | 역학·열·재료·센서 모델의 정밀 결합 | 타당성 평가에 맞는 전문 솔버 | **후속 5~12개월** |

**2D → 3D는 단순한 렌더링 교체가 아니다.** 2D에서 생략한 높이·부피·회전·접촉·자중·위치 제약이 추가되면 이미 검증한 행동의 실행 가능성이 달라질 수 있다. 3D 통합 시 논리 코어의 규칙은 유지하되 공간/물리 제약은 별도로 재검증한다.

초기 2D 세계 예시(잠정): 작업 셀 4~8개, 연결 3~12개, 작업 도착·대기·선행관계·자원 예약·구조 변경 1종. 이 숫자는 구현 가이드일 뿐 요구 성능이나 최종 도메인을 확정하지 않는다.

## 3. 세계 상태의 권위(State Authority)와 일관성

**하나의 상태변수에 대해 한 시점에 하나의 권위 있는 계산 주체만 존재해야 한다.** 특히 Python 코어와 3D 엔진이 같은 물체 위치를 독립적으로 적분하는 설계는 금지한다.

| 상태 종류 | 권위 주체(초안) | 동기화 규칙 |
|---|---|---|
| 작업 상태, 자원 예약, 구조 버전, 논리 이벤트 | 논리 코어 | 원자적 상태 변경 후 이벤트 발행 |
| 물체의 `pose`, `velocity`, `contact` 등 3D 동역학 | 해당 구간의 **지정된 물리 솔버** | 솔버 결과를 통합 상태에 반영한 뒤 이벤트/관측 생성 |
| 2D 경로·논리 공간 배치 | 도메인 모델 | 3D 제약이 추가되면 실행 가능성 재검사 |
| 시각화 카메라·색상·보간 프레임 | 렌더러 | **시뮬레이션의 참값을 수정하지 않음** |
| 원인 참값·숨겨진 고장·미래 입력 | 실험 환경/평가기 전용 저장소 | 내부 AI·일반 로그에 누출 금지 |

시뮬레이션은 `WorldState`와 `Event`를 최종 외부 인터페이스로 제공하되, 각 상태 필드의 **소유자·갱신 주기·단위·오류 처리 방식**을 명시한다. 물리 엔진이 상태를 반환할 때 검증된 동기화 경로로만 세계에 반영한다. 외부의 구조 변경 요청은 `validate → apply → event` 경계를 통과해야 한다.

## 4. 시계·스텝·결합 방식(Co-simulation)

```text
Logical Sim Clock : arrival / completion / allocation / reconfiguration events
Physics Step Clock: numerical integration and contact/constraint resolution
Render Clock      : interpolation and drawing (non-authoritative)
```

- `sim_time`, `step_id`, `world_version`, `model_version`을 최소 추적 필드로 둔다.
- 논리 이벤트가 물리 시스템에 영향을 주면 **입력 설정 → 물리 스텝 실행 → 상태 수집 → 제약 확인 → 이벤트 커밋**의 순서를 정의한다.
- 연결 시 경계 시간(`t₀→t₁`), 데이터 샘플링, 단위 변환, 보간/외삽 허용 여부, 지연 처리 규칙을 명시한다.
- 일괄 실행·저장·재생을 **기본 경로**로, 실시간 양방향 상호작용을 **검증 후 추가하는 경로**로 다룬다.
- 물리 솔버 간 반복 결합(강결합/약결합), 안정적인 시간 간격, 오차 허용치는 장기 단계에서 실험으로 정한다. 실시간 렌더 프레임률을 물리적 시간 정확도의 대리 지표로 사용하지 않는다.

동일 시드·설정으로 **논리 사건의 재현성**을 목표로 한다. 물리 엔진·병렬 계산·외부 LLM은 완전한 비트 단위 결정성을 보장하지 않을 수 있으므로 재현 가능 범위와 허용 오차를 별도로 기록한다.

## 5. 3D 공간 엔진과 물리 엔진을 어떻게 선택할까?

게임 엔진 **사용 가능** ≠ 게임 엔진 **사용 필수** ≠ 공학용 물리 정밀도 **보장**.

| 분류 | 후보(미확정) | 적합한 역할 | 한계/검증할 점 |
|---|---|---|---|
| 3D 실시간 엔진 | Godot / Unity | 공간 편집, 객체 배치, 조작 UI, 기본 충돌/시각화 | 내장 물리의 정확도·계산 소유권을 별도 확인 |
| 웹 3D 렌더러 | Three.js | 설치 부담이 적은 포트폴리오 시연 및 원격 조회 | 자체적으로 산업용 물리 솔버가 아님 |
| 전문 역학 솔버 | MuJoCo | 관절·접촉·로봇의 제어 실험 | 공장 전체 운영·열·재료 해석을 자동 제공하지 않음 |
| 로봇 시뮬레이션 | Gazebo | 센서·로봇·ROS 계열 연동, 물리 엔진 통합 | 로봇 중심 워크플로의 복잡성 |
| 산업 디지털 트윈 생태계 | OpenUSD / Omniverse / Isaac Sim | 3D 자산 교환, 산업/로봇 시뮬레이션 확장 | RTX 4070 Ti 12GB/32GB RAM에서 고충실도 장면 제약 가능 |
| 다중 물리 모델 연결 | FMI/FMU, Modelica 기반 모델 | 기존 물리 모델 재사용 및 공동 시뮬레이션 | 단위·시계·솔버·검증 계약 필요 |

최초 12주는 3D 장면을 **기술 선택 실험**으로 비교하되 최종 엔진을 이 문서에서 고정하지 않는다. 간단한 움직임의 충돌 판정에는 선택된 3D 엔진의 내장 물리를 사용할 수 있지만, *공학적 성능 주장의 근거*로 삼는 경우에는 정확도 평가나 전문 솔버와의 대조가 필요하다.

## 6. 모델 등록·물리 법칙 합성·분리(장기 연구를 위한 계약)

모델은 물리 법칙 전체를 무조건 켜는 방식이 아니라 **입출력·가정·적용 영역을 등록**하여 필요한 것만 연결한다.

```yaml
model_id: motor_thermal_simplified
version: 0.1-draft
inputs: [{name: heat_loss, unit: W}]
outputs: [{name: temperature, unit: K}]
assumptions: [lumped_thermal_mass]
valid_range: {temperature_K: [273, 423]}
update_interval_s: 0.1
fidelity: simplified
owner: thermal_solver
```

모델 간 문제를 물리 법칙끼리의 '충돌'이라고 부르기보다 **가정·단위·좌표계·유효 범위·갱신 시점·결합 안정성의 불일치**로 정의한다. 12주에는 전체 모델 레지스트리 구현이 아니라 **최소 연결 계약과 불변조건**만 두고, 모터 열화·하중·열-운동 연성 등은 후속 실험 후보로 유지한다.

## 7. 정보 복잡도 및 정밀도(Fidelity) 선택

- **저정밀:** 작업 흐름·대기열·평균 이동시간·집계 자원.
- **중간 정밀:** 개별 객체의 경로/위치와 단순 접촉·충돌.
- **고정밀:** 실제 형상·동역학·열·재료 등 선택 영역의 상세 모델.

평상시 저비용 관측을 사용하다가 **이상 신호와 모델 의존성**에 따라 일부 영역의 정밀도를 높이는 아이디어는 장기 연구에 포함한다. 정밀도 전환 시 상태 매핑과 손실, 계산 비용, 진단 향상, 오탐·미탐을 기록하며 상시 고정밀보다 항상 우월하다고 가정하지 않는다.

## 8. 12주 안에 시행할 최소 통합 검증

1. Headless에서 동일 시나리오를 여러 번 실행하고 사건/상태를 저장한다.
2. 2D 뷰에서 작업·연결·정책 행동·재구성 이력을 검증한다.
3. 동일한 세계/사건 일부를 **별도 3D 렌더러**에서 재생한다.
4. 실제 3D 고유 제약(예: 서로 다른 높이의 경로 교차, 물체 점유/충돌, 수직 이동 가능성)을 **물리 또는 기하학 검증기**로 검사한다.
5. 가능/불가능한 구조 변경 요청과 논리/물리 상태 불일치를 독립 로그로 남긴다.
6. 엔진의 성능(실험 처리량, 물리 스텝 시간, CPU/GPU 프레임 시간)을 각각 계측한다.

**합격 기준:** 화면이 동작하는 것만으로 완료가 아니다. 3D에서 추가된 제약 때문에 2D의 가정이 깨질 수 있음을 재현하고, 검증 결과가 행동 허용/거절 또는 모델 수정 기록으로 연결되어야 한다.

### 8.1 시행 결과 (2026-11-12, 결정 0007)

| 항목 | 결과 |
|---|---|
| 1. headless 반복·저장 | 기록된 실험 1,495회, 사건 로그 바이트 단위 재현 |
| 2. 2D 뷰 | `asel view`: 작업·연결·재구성 이력 |
| 3. 별도 3D 렌더러에서 재생 | `asel view3d`: 같은 공개 사건 로그를 Three.js 로 재생 (읽기 전용) |
| 4. 3D 고유 제약 검사 | 셀별 천장 높이 vs 역할의 필요 높이 (**기하 검증, 물리 아님**). 2D 에서 되던 전환이 3D 에서 불가능 (P1 처리 시간 338 → 378 s) |
| 5. 가능/불가능 요청 기록 | 천장에 막힌 옵션은 후보에서 빠지고, 직접 제출하면 엔진이 거절해 공개 로그에 남는다. 3D 화면이 둘 다 표시 |
| 6. 성능 계측 | 실험 처리량(배치 기록), 3D 한 장 그리기 평균 0.33 ms (셀 9개, RTX 4070 Ti). 물리 스텝은 해당 없음 |

**충실도 한계:** 물리 엔진 없음, 정적 배치, 이동체·경로 없음, 높이 하나(천장)만 검사한다. 3D 화면은 엔진 판정의 시각화이며
3D 공간의 다른 제약(점유·충돌·수직 이동)은 검증하지 않았다. 2D·3D 결과를 현실 성능으로 주장하지 않는다.

## 9. 하드웨어·성능 및 현실 적합성

환경: **RTX 4070 Ti 12GB VRAM, Ryzen 5 7600(6C/12T), RAM 32GB**.

- Headless 대량 실험은 렌더러·그래픽 프레임과 독립적으로 실행한다.
- 시각화는 메시·재질 재사용, instancing, LOD, 필요 영역만 활성화하는 방식 등을 고려한다.
- 작업 처리량/정책 품질과 **FPS/VRAM**을 혼동하지 않는다. 1080p/60 FPS는 필요 시 설정하는 벤치마크 **목표값**이지 보장 수치가 아니다.
- Isaac Sim 등 고부하 플랫폼은 초기 필수가 아니다. VRAM·RAM·센서 수·물리 스텝을 실제 시험하고 필요한 경우 일부만 선택적으로 사용한다.
- 합성 시뮬레이션 테스트베드를 실제 설비 상태와 지속 동기화하는 **디지털 트윈**이라고 단정하지 않는다. 실제 적용 가능성 주장은 현실 자료를 사용한 검증·타당성 평가·불확실성 분석을 요구한다.

- [ ] 상태 권위: 각 필드 소유자와 물리/논리 결과의 커밋 순서 기록.
- [ ] 관측 격리: 내부 AI에 숨겨진 참값·미래 수요·주입된 고장 원인 누출 없음.
- [ ] 물리 검증: 기하학/충돌 결과가 작업 실행 가능성에 반영됨.
- [ ] 복합 모델 계약: 단위·좌표계·시간·유효 범위가 문서화됨.
- [ ] 재현성: 설정·시드·소프트웨어 버전·결과 기록.
- [ ] 3D 표현 교체: 시각화 교체만으로 논리 사건이 바뀌지 않는 범위 확인.
- [ ] 실제 산업 데이터가 없는 경우 일반화·정확도 주장 제한.

**후속 5~12개월:** 전문 로봇/물리 솔버 연동, FMI/FMU 또는 Modelica 모델 결합, 복합 물리·선택적 정밀도, 재난·장애 상황의 방어적 복원력 평가, 공간적 구조 재설계의 장기 안정성 검증. 해당 항목은 12주 필수 구현 범위가 아니다.
