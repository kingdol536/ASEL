# 07. 실험 설계·재현성·공진화 검증

> 상태: **실험의 공정성 원칙은 확정 / 최종 성공 지표와 주가설은 세부 실험마다 미결정**

## 1. 실험의 목적

'생산성이 몇 % 향상됐다'로 연구의 유효성을 평가하지 않는다. 목표는 **이질적인 구조를 공통 메커니즘으로 표현·제어·변경할 수 있는지**, 그 과정에서 발생하는 새로운 제약/병목을 **인과적으로 설명하고 재현할 수 있는지**에 있다.

처리량·지연·비용은 유용할 수 있으나 메커니즘을 증명하기 위한 **조건부 결과 변수**이지 고정된 유일한 주지표가 아니다.

## 2. 실험별 프로토콜(필수)

각 실험을 아래 형식으로 저장한다.

```yaml
experiment_id: EXP-001
question: '문제/현상에 대한 질문'
hypothesis: '반증 가능한 주장'
status: planned
scenario_family: 'warehouse_A'
controlled_variables: []
independent_variables: []
outcomes: []             # 실험별 선정; 최종 공통 지표 미확정
baselines: []
policies: []
seeds: []
heldout_scenarios: []
termination_rules: []
analysis_plan: '사전 지정한 효과·신뢰구간·한계'
model_versions: {}
code_revision: ''
```

시작 전에 가설·주요 비교·평가 방법을 고정하고 이후 변경 시 기록한다. 결과를 본 뒤 지표를 바꾸었다면 탐색적 분석으로 표시한다.

## 3. 검증의 세 수준

1. **구현 검증(Verification):** 코드/모델이 자체 명세대로 동작하는가(불변조건, 단위 테스트, 경계 사례)?
2. **시뮬레이션 타당성(Validation):** 모델이 의도한 현상을 적절히 대표하는가(가정·전문가 피드백·공개 데이터 대조)?
3. **연구 가설 평가:** 정책/메커니즘이 기준선보다 어떤 조건에서 좋은지, 또는 나쁜지 입증하는가?

하나가 다른 두 개를 대체하지 않는다.

## 4. 비교 정책 후보(확정 아님)

| 실험 질문 | 후보 기준선 | 실험 처리군 |
|---|---|---|
| 구조 변경 효과 | 고정 구조, 운영 최적화만 수행 | 비용 고려 재구성 |
| 협력/권한 효과 | 단일 정책, 규칙 기반 통합 제어 | 역할 분리·검증기 포함 |
| 이식성 | 환경 A에만 맞춘 도메인 정책 | 공통 인터페이스+환경 B 어댑터 |
| 모델 정밀도 | 저정밀만, 고정밀만 | 조건부 상세 모델 활성화(후속) |

**주의:** 일부 정책이 주어지는 정보량/연산 자원이 더 많다면 같은 조건이라고 말할 수 없다. 자원·정보 예산을 동일하게 하거나 차이를 실험 변수로 선언한다.

## 5. 후보 관측 지표 은행(최종 결정 아님)

| 연구 질문 | 가능한 측정값 | 왜 불충분할 수 있나 |
|---|---|---|
| 구조를 이해하는가 | 노드/관계 파악 정확도, 누락·오인 비율 | 구조적 의미를 놓칠 수 있음 |
| 제약을 지키는가 | 금지 행동 거절율, 잘못된 거절, 위반 수 | 모두 거절해도 높은 안전 점수 |
| 목표 변화에 적응하는가 | 변경 성공률, 변경시간, 재구성 영향 | 쉬운 목표만 선택할 수 있음 |
| 공통 제어가 이식되는가 | 코어 수정량, 어댑터 변경량, 기능 통과율 | 환경 B가 A와 너무 비슷할 수 있음 |
| AI 역할이 효과적인가 | 유효한 행동 비율, 조정 지연, 비용 | 역할 분리 자체의 장점 증명 불가 |
| 병목이 이동하는가 | 병목 위치·유형, 전환 비용, 파급 효과 | 외부 수요 변화가 원인일 수 있음 |
| 운영상 가치가 있는가 | 작업 완료율, P95 지연, 비용 | 연구의 유일한 성과 지표는 아님 |
| 3D 결합이 타당한가 | 공간 제약 위반, 충돌/위치 불일치 | 실제 물리적 현실성 별도 문제 |

선정 전 각 지표에 **측정 단위·수집 경로·정답 산정 방식·허용 오차·오용 위험**을 명시한다.

## 6. 초기 공진화 실험 제안

**가상 환경 A:** 고정된 셀/경로에서 일부 작업이 집중되는 조건.

- `P0`: 고정 운영/구조.
- `P1`: 지연을 줄이려는 구조 재구성.
- `P2`: `P1`에 변경 비용과 최소 유지시간을 추가.

설명하려는 연쇄:

```text
수요 변화 -> 기존 병목 -> 구조 변경
         -> (가능한) 변경 비용/조정 충돌
         -> 안정화 정책 -> (가능한) 반응 지연
```

괄호 부분은 **관측할 현상이지 이미 증명된 결과가 아님**. 현상이 발생하지 않으면 외생 변수와 모델 구조를 검토하며 부정적 결과를 보존.

## 7. 첫 이식성 실험 제안

- 학습/조정은 환경 A에서 진행.
- 독립 검증용 환경 B는 작업 의존성·자원 경합·전환 비용 등의 관계를 다르게 구성.
- 평가 전 환경 B를 보고 공통 제어기 코드를 변경하지 않는 것이 원칙. 변경이 필요하면 **그 수정량과 이유를 결과로 보고**.
- 단 2개 환경 성공을 전 산업 범용성 증명으로 해석하지 않는다.

## 8. 반복·통계 방법

- 독립 시나리오별 시드 집합을 나누어 각 정책에 **대응 쌍(공통 난수 환경)** 적용.
- 초기 안내용 반복 수로 시나리오당 30회 등을 고려할 수 있으나, **충분한 표본 수는 효과 분산·목표 정확도로 결정**.
- 평균/중앙값, 분포·꼬리 위험, 대응 차이의 신뢰구간을 함께 공개.
- 여러 지표를 무작위로 뒤져 좋은 것만 골라 '검증됨'이라고 주장하지 않는다.
- 미관측 수요/장애 분포로 최종 평가하며 정책을 다시 조정하면 holdout이 아니다.

## 9. 절제 실험과 반례

필요한 경우 기능을 하나씩 제거한다.

- 구조 변경 기능 제거.
- 검증기 제거(불변조건 자체가 깨지는 위험 실험은 격리된 비프로덕션 환경에서만).
- 전환 비용 고려 제거.
- 역할 통신/공유 관측 제거.

반례: 정책이 고정 방식보다 나빠지는 환경, 호출 비용이 커지는 상황, 새로운 구조에서 작동이 실패하는 상황도 결과에 포함.

## 10. 3D 검증 추가

- 2D에서 유효한 정책을 3D로 연결할 때 충돌·높이·물리 위치 때문에 생긴 위반을 독립적으로 기록.
- 3D의 물리 검사는 논리 정책 시험의 대체가 아니라 **새로운 제약에 대한 별도 검증**.
- 렌더링 FPS는 연구 목적 지표와 분리.

## 11. 데이터·보고서 레이아웃(후보)

```text
experiments/configs/EXP-001.yaml
experiments/runs/<experiment>/<run_id>/events.ndjson
experiments/runs/<experiment>/<run_id>/metrics.json
experiments/runs/<experiment>/<run_id>/manifest.json
experiments/reports/EXP-001.md
```

manifest 필수 정보: 코드 커밋, 설정 해시, 시드, 라이브러리 버전, 정책/AI 버전, 시작/종료 시각, 시뮬레이션 시간, 평가기 버전. 외부 LLM 비결정성이 있으면 재현 가능한 로그/응답 캐시와 한계를 기록.
