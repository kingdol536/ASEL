# 04. AI 주체·정책·관측·권한 시스템

> 상태: **역할 구성 및 권한 배분 미결정**, 통신·검증 경계는 확정 원칙.

## 1. 먼저 구분할 세 가지 AI

1. **개발 도구:** Claude Code 등 코드 작성·수정용 도구. 시뮬레이션 내 의사결정 주체가 아니다.
2. **세계 내부의 AI/정책:** 관측을 받고 행동을 선택하며 목표·제약 아래 움직이는 주체. LLM, 최적화기, 규칙 기반, 학습 정책 모두 가능.
3. **세계 외부의 실험/평가 시스템:** 숨겨진 실제 상태를 이용해 실험을 생성·검증. **세계 내부 AI에 정답 제공 금지**.

## 2. 역할은 고정 명단이 아니라 변경 가능한 구성

다음은 **후보 역할**이며 최종 역할 수·계층·권한은 실험을 통해 결정한다.

| 후보 | 가능 기능 | 예상되는 실패 가능성 |
|---|---|---|
| 전략/목표 해석 | 목표 변화 해석, 대안 비교, 목표 간 충돌 식별 | 잘못된 추상화·목표 왜곡 |
| 구조 설계/재구성 | 연결, 공간 배치, 작업 셀 기능 변경 제안 | 전환 비용 과소평가 |
| 운영/자원 조정 | 작업 경로·자원 할당·우선순위 결정 | 국소 최적·경합 |
| 지역 제어 | 특정 모듈의 짧은 주기 행동 | 전체 맥락 부재 |
| 관측/진단 | 장애·병목·모델 불일치 가설 | 오탐·원인과 상관 혼동 |
| 협력/조정 | 주체 간 합의·충돌 조정 | 통신비용·교착상태 |
| 평가/검증 | 기준 검사·성능 판정 | 운영 주체와 합쳐질 경우 정답 누출 위험 |

마지막 평가 역할은 구현 위치에 따라 **독립 검증기** 또는 시험 보조 AI가 될 수 있다. 정답을 아는 실험 평가자는 내부 운영 주체에 포함하지 않는다.

## 3. 환경 접근권한의 최소 계약

권한 종류의 예: `observe(scope)`, `propose(action_type)`, `request_approval`, `read_logs(scope)`, `call_model`, `reconfigure(scope)`.

- `grant`는 주체별 설정 가능하도록 구성하되 **누구에게 무엇을 부여할지**는 최종 확정하지 않는다.
- 정책은 허가된 입력만으로 결과를 만든다. `hidden_ground_truth`, `future_demand`, `injected_fault_cause` 접근 금지.
- 주요 구조 변경은 실행 전 독립 검증 단계를 거친다.
- 시뮬레이터의 실제 상태는 오직 실행 엔진만 수정한다.

## 4. Agent/Policy 인터페이스(초안)

```python
class PolicyAdapter(Protocol):
    def reset(self, context: PolicyContext) -> None: ...
    def decide(self, observation: Observation,
               affordances: list[ActionSpec]) -> list[ActionProposal]: ...

class ActionProposal:
    actor_id: str
    action_type: str
    target_id: str
    parameters: dict
    expected_world_version: int
    reason: str | None
```

프로토콜은 단일/다중 AI, 규칙·최적화 정책을 같은 실행 스케줄러에 연결하기 위한 **개념 예시**다. 실제 언어/타입은 변경 가능.

## 5. 오케스트레이션: 호출 빈도와 결정 주기 분리

- 물리 프레임(예: 초당 60회)마다 LLM을 호출하지 않는다.
- 작업 도착, 고장 징후, 목표 변경, 주기적 계획 갱신 등 **이벤트 기반 호출**을 우선 고려한다.
- 오래 걸리는 AI 응답에는 타임아웃·버전 검증·취소·대체 정책을 둔다.
- 비용은 `token/call`, 지연시간, 실패율과 함께 기록 가능하도록 설계. 실제 API 비용은 후속 확정.

## 6. AI의 역할 실험

역할 구성은 미리 우월하다고 가정하지 않는다. 실험 후보:

- **단일 중앙 정책:** 동일 관측 접근과 예산 하에 한 AI가 의사결정.
- **역할 분리:** 제한된 관측을 갖는 여러 정책 주체가 정보를 공유.
- **혼합형:** 국소 규칙 기반 제어 + 필요 시 전략/진단 AI 호출.
- **독립 검증기 추가:** 같은 제안·예산 조건에서 안전한 행동만 통과시키는 구조.

각 실험에서는 모델 버전, 허용된 도구, 입력 정보, 토큰/시간/호출 예산을 기록한다. 비교 결과 없이 멀티 에이전트가 더 좋다고 단정하지 않는다.

## 7. 외부 전지적 관찰자와의 명확한 분리

```text
Hidden World Truth -----> Experiment Evaluator (private)
         |
         +-- Sensor / Observation Projection -> Agent/Policy (public subset)
                                                   |
                                              Action Proposal
                                                   |
                                        Contract/Policy Validator
                                                   |
                                           Environment Actuator
```

정보 유출 자동 테스트:

1. 관측 직렬화 결과에 private key가 나타나지 않는다.
2. 도구 호출에서 `get_hidden_state()` 같은 기능이 등록되지 않는다.
3. 실험 설정에 미래 수요가 있어도 정책 실행 시 미래 입력을 직접 조회할 수 없다.
4. 로그를 공개할 때 비공개 정답과 혼합되어 재유출되지 않는다.

## 8. AI 모델 연결 제안

`MockPolicy`(결정론적 단위 테스트) → `Rule/OptimizationPolicy`(기준선) → `LLMPolicy`(실제 모델 어댑터) 순으로 연결한다. Claude API 사용은 개발용 Claude Code 구독과 별개일 수 있으므로 연동 방식·비용을 확인한 뒤 결정한다.

모델 출력은 **구조화된 스키마**로 검증하며 자연어 자유 응답을 환경 상태 변경 명령으로 직접 파싱·적용하지 않는다. 모든 행동은 허용 목록을 거친다.

## 9. 진화 가능성을 위한 설계

- 역할 이름과 에이전트 수를 코어에 하드코딩하지 않는다.
- 역할 그래프(상호작용), 권한 그래프(허가), 의존성 그래프(업무)를 혼동하지 않는다.
- '역할 분리' 자체가 목표가 아니라 **어떤 조건에서 역할 분리가 유리한지 발견**하는 것이 연구의 일부다.
- 후속 연구: 역할의 동적 분할·병합, 위기 상황에서 접근권한 격리, 정책 충돌 탐지.
