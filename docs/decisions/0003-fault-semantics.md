# 0003. 셀 고장 의미: 새 작업만 막고 진행 중 작업은 끝까지

- 상태: **잠정** (2026-11-11, 사용자 승인한 기본값)
- 관련: 티켓 #4, `docs/03` §4, `docs/04` §3

## 맥락

M2 시험 세트에 '자원 장애'가 필요하다. 고장이 났을 때 이미 그 셀에서 돌고 있던 작업을
어떻게 처리할지는 설계 문서에 정해져 있지 않다.

## 후보안

| 안 | 내용 | 비용 |
|---|---|---|
| A. 진행 작업 완료 허용 | 고장 단위만큼 새 작업 시작을 막고, 진행 중 작업은 끝까지 처리 | 고장 직후 잠시 '고장 중인데 일하는' 상태가 생김 |
| B. 진행 작업 중단·재대기 | 고장 즉시 작업을 READY 로 되돌리고 자원 해제 | RUNNING→READY 전이, 진행률·재작업 규칙 필요 |
| C. 진행 작업 실패 | 작업을 FAILED 로, 주문 단위 재생성 규칙 필요 | 실패 후 처리 정책이 또 필요 |

## 선택과 이유

**A.** 상태 전이 표와 불변조건을 바꾸지 않고 구현할 수 있는 가장 단순한 규칙이다.
고장 효과(새 작업 불가 → 대기 누적)를 관찰하는 M2 목적에는 충분하다.

## 구현 요약

- 자원에 `out_of_service`(고장 단위 수)를 둔다. 새 작업 가용량 = 용량 − 고장 − 예약.
  고장 중 진행 작업이 남아 있으면 가용량이 음수가 될 수 있다.
- 불변조건: `0 ≤ out_of_service ≤ capacity`, `reserved ≤ capacity` (기존 유지).
- 공개 로그: `ResourceOutageStarted/Ended {units}` (관측 가능한 증상).
  비공개 로그: 원인(`cause`), 계획된 종료 시각(`planned_end_s`).

## 대안 포기 비용

현실의 많은 고장은 진행 작업을 중단시킨다. A 는 고장 영향을 과소평가할 수 있다.

## 위험

- 고장 효과가 실제보다 약하게 나와 M4 병목 실험의 결론이 달라질 수 있다.

## 재검토 조건

- M4/M5 실험에서 고장 대응 정책을 비교할 때
- 진행 작업 중단이 연구 질문에 필요해질 때 (B/C 는 상태 전이 표 변경과 결정 기록 필요)
