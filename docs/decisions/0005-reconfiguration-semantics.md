# 0005. 셀 재구성(역할 전환) 규칙

- 상태: **잠정** (2026-11-11, 사용자 승인한 티켓안 #20 기준)
- 관련: 티켓 #20, docs/03 §3(구조 변경과 작업 처리 분리), docs/06 §2(느린 구조 제어), EXP-002

## 맥락

M4 는 '구조 변경 → 전환 비용 → 새 병목'을 관찰한다. 구조 변경의 최소 단위로 **셀의 역할(capability) 전환**을 둔다.
진행 중 작업, 정지 시간, 고장과의 겹침, 교착을 어떻게 다룰지 정해야 한다.

## 후보안

| 안 | 내용 | 비용 |
|---|---|---|
| A. 비우고 전환 (drain) | 요청 → 새 작업 중단 → 진행 작업 완료 → `changeover_s` 정지 → 새 역할 | 비우는 동안 용량 손실이 생김 (현실적인 전환 비용의 일부) |
| B. 빈 셀만 전환 | 셀이 비어 있을 때만 요청 수락 | 구현이 가장 단순하지만 부하가 높으면 전환 기회가 거의 없음 |
| C. 즉시 중단 | 진행 작업을 중단하고 바로 전환 | 중단 작업 재대기 규칙과 상태 전이 표 변경 필요 |

## 선택: A

- **이벤트:** `ReconfigurationRequested`(목표 역할) → `ReconfigurationStarted`(전환 시간) → `ReconfigurationCompleted`(새 역할). 모두 공개 이벤트다(구조와 전환 시간은 운영자가 아는 설계 정보).
- **비우는 중(draining):** 새 작업 시작을 거절한다. 셀이 비어 있으면 요청 즉시 전환이 시작된다.
- **전환 중(changeover):** 작업 없음. `changeover_s` 가 지나면 환경이 완료를 적용한다.
- **역할은 완료 시점에만 바뀐다.** 중간에 일부만 바뀐 상태는 없다. 완료 시 `structure_version` 이 1 증가한다.
- **교착 방지:** 전환 결과 어떤 capability 의 제공 셀(용량 > 0)이 0개가 되면 요청을 거절한다.
  전환 중·비우는 중인 셀은 목표 역할로 센다. 고장은 일시적이므로 계산에서 빼지 않는다.
- **고장과의 겹침:** 독립이다. 고장 중에도 전환은 진행·완료되고, 고장 단위는 전환 뒤에도 유지된다.
- **취소·연쇄 요청 없음:** 비우는 중·전환 중인 셀에 새 요청은 거절한다.
  이유: 히스테리시스(P2)는 '요청을 늦추는' 방식이라 취소가 필요 없고, 취소를 넣으면 상태 전이와 정지 시간 회계가 복잡해진다.
- **권한:** 요청은 구조 제어 주체만, 완료는 환경만 한다. 배정 주체는 재구성을 할 수 없다.

## 대안 포기 비용

- C 를 택하지 않아, '급하게 바꿔야 하는데 긴 작업이 진행 중'인 상황의 비용은 비우는 시간으로만 반영된다.

## 위험

- 비우는 시간이 처리 시간 분포에 좌우된다(지수 분포라 긴 꼬리). P1 이 자주 전환하면 비우는 시간이 누적될 수 있다 — 이것도 관찰 대상이다.
- 교착 방지 규칙은 '제공 셀이 있다'만 보장하고 '충분하다'는 보장하지 않는다.

## 검증

`tests/test_reconfiguration.py`: 비우기→전환→새 역할, 빈 셀 즉시 전환, 마지막 제공 셀 전환 거절(용량 0 셀 제외),
목표 역할 기준 제공 판단, 요청 검증·권한, 고장 겹침, 시뮬레이터 완료 자동 예약·재현·재생, 시나리오 스키마, 무작위 행동열(불변조건·제공 셀 유지·재생).

## 재검토 조건

- M4 실험에서 비우는 시간이 결과를 지배하는 것으로 측정될 때 (B/C 비교 실험 후보)
- 셀이 여러 capability 를 동시에 갖는 옵션이 필요해질 때
