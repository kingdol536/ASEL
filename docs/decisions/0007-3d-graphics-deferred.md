# 0007. 3D 그래픽은 후순위, 3D 공간 제약은 엔진 기능으로 (안 A)

- 상태: **확정** (2026-11-11, 사용자 결정)
- 관련: R-04, docs/05 §8, docs/09 M6, 티켓 #30, #40(T7)

## 맥락

M4 까지 마친 시점에서 사용자가 우선순위를 정했다: **여러 산업 구조에 이식하고 AI(AX)를 곧바로 연결할 수 있는 엔진을 다듬는 것**이 먼저이고, 3D 그래픽은 나중에 한다.
그런데 R-04(확정)와 M6 완료 조건에는 "12주 안에 최소 3D 통합 장면에서 3D 고유 제약 하나 검증"이 들어 있다.

## 후보안

| 안 | 내용 |
|---|---|
| A | 3D **그래픽**만 미룬다. 3D **공간 제약**(높이·점유 등)은 화면 없이 엔진 기능으로 12주 안에 넣는다 |
| B | 3D 를 통째로 12주 이후로 옮긴다 (R-04 를 장기 확장으로) |

## 선택: A

공간 제약도 결국 엔진이 다뤄야 하는 제약이다. 그래픽 없이도 "2D 에서 유효했던 구조 변경이 3D 제약 때문에 불가능해진다"를 검증할 수 있다 (docs/05 §2: 2D → 3D 는 렌더링 교체가 아니다).

## 바뀌는 것

- R-04: 12주 범위의 3D 는 **화면 없는 공간 제약 검증**. 3D 시각화(그래픽 재생 장면)는 후순위 (12주 후반 또는 후속).
- M6: "최소 3D 공간·물리 사례"를 "3D 공간 제약 하나를 엔진에서 검증 + 근거 데이터"로. 그래픽 영상은 필수에서 선택으로.
- #15(3D 엔진 시험)는 열린 채 보류한다. 사람이 눈으로 보는 증거의 중요성은 유지한다 (그래픽을 만들 때 4가지 장면 제안 참고).

## 대안 포기 비용

- 12주 포트폴리오에 3D 시각 데모가 없을 수 있다. 2D 뷰어와 데이터로 대신 보여준다.

## 재검토 조건

- M5 완료 후 남은 기간이 충분할 때 (그래픽 재생 장면을 다시 검토)

## 재검토 결과 (2026-11-12, 사용자 결정: "EXP-003 보고서 → M6 마무리·병합 → 3D 그래픽 재생" 순서)

- 조건 충족(M5·M6 완료, 마감까지 80일 이상)으로 **3D 그래픽 재생을 추가**했다. 안 A 의 구조는 그대로다:
  공간 제약의 판정은 엔진(`roles_over_ceiling`)이 하고, 그래픽은 그 결과를 보여주는 **읽기 전용 재생기**다.
- 구현: `asel scene3d` (공개 사건 로그 → 장면 JSON, #57), `asel view3d` (Three.js 0.170.0 을 넣은 HTML 한 파일, #58).
  2D 실행을 3D 배치 위에 겹쳐 보면 "2D 에서 되던 전환이 3D 천장 때문에 불가능"한 순간이 빨간색으로 보인다.
- 상태 권위: 셀 위치는 시나리오의 정적 배치뿐이고 화면은 위치를 계산·갱신하지 않는다 (CLAUDE.md §3).
- 하지 않은 것: 물리 엔진, 이동체, 대규모 장면(설비 20~100개) 측정, Godot 비교 → #15 (후속).
- 측정·화면: [M6 게이트 보고서 §3.7](../../experiments/reports/M6-gate.md), 상태: **확정 유지** (그래픽은 선택 항목을 채운 것).
