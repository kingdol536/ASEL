# 0004. Claude 정책: 모델 선택, 예산 가드, 응답 캐시

- 상태: **잠정** (2026-11-11). 모델 선택은 사용자가 자율 판단으로 위임함. EXP-001 승인 시 재확인
- 관련: 티켓 #11 #13, `experiments/plans/EXP-001.md`, R-06(AI 역할 미결정)

## 맥락

- M3 에서 '실제 AI 연동 경로'가 필요하다 (docs/01 §3).
- API 예산: 프로모션 크레딧 **$55 상한**, 2026-11-19 만료. 상한이지 소진 목표가 아니다.
- 정책 결정은 실행 한 번에 수백 번 일어난다 (사건 기반, 후보가 있을 때마다).
- 결정 과제는 좁다: 관측과 후보 목록을 보고 '어떤 작업을 어느 셀에' 고르기.

| Claude Haiku 5.5 `claude-haiku-5-5` | $0.10 / $0.50 (프롬프트 100K 초과 시 $0.50 / $2.50) | **기본값.** 좁은 선택 과제에 맞고, 예산 안에서 반복 실험 표본을 확보할 수 있음 |

### 비용 추정 (가설 — 파일럿으로 측정 필요)

결정 1회 입력 약 3~8K 토큰(관측 JSON), 출력 약 0.3~1K 토큰(적응형 사고 포함, effort low) 으로 가정하면:
- Haiku 5.5: 결정당 약 $0.0005~0.0013 → 실행(약 300 결정)당 약 $0.15~0.4 → 90회 약 $14~36
- Sonnet 5.5: 그 약 20배 → 실행당 $3~8

이 숫자는 측정이 아니다. EXP-001 파일럿(6회)으로 실제 비용을 재고 본 실험 규모를 정한다.

## 선택

- 모델: Haiku 5.5 기본, effort `low`, `max_tokens` 2048, 구조화 출력(`output_config.format` json_schema).
  강제 tool_choice 는 일부 현행 모델에서 400 이므로 쓰지 않는다.
- **기본 모드는 replay**(캐시만, 비용 0). 비용이 드는 `record` 는 `ASEL_LLM_MODE=record` 로 명시해야 한다.
- **예산 가드 (예약 → 정산):** 호출 전 최악 비용(입력 과대 추정 + max_tokens 전부 출력) × SDK 시도 수(재시도 포함)를
  잠금 안에서 상한과 비교하고 **예약**한다. 호출 뒤 실제 사용량(`usage.input_tokens/output_tokens/cache_*`)으로 **정산**한다.
  실제 비용을 알 수 없는 실패(타임아웃·연결 오류·5xx)는 예약액 전부를 지출로 남긴다(보수적). 429·4xx 는 0 으로 정산.
  장부는 저장소 밖 파일, 실행·배치·프로세스를 넘어 누적되고 잠금 파일로 동시 갱신을 막는다. 호출 상한은 '시도 수' 기준.
  Claude 정책 일괄 실행은 jobs=1 만 허용.
- **응답 캐시:** (녹화 묶음 이름 `cache_tag` + 요청 전체)의 해시를 키로 저장소 밖(`%LOCALAPPDATA%\asel\llm\cache`)에 저장.
  같은 시드·같은 응답이면 사건 로그가 바이트 단위로 재현된다. 녹화 중 실패가 있었어도 같다
  (공개 로그의 대체 이유는 'fallback' 하나로 통일하고, 자세한 사유는 사용량에만 기록).
  실제로 응답한 모델 버전(`served_models`)을 실행별 사용량에 기록한다. 모델이 바뀌면 `cache_tag` 를 바꿔 다시 녹화한다.
- **실패 처리:** 타임아웃·연결 오류·요청 한도·거절(`refusal`)·출력 잘림·형식 오류는 그 결정만 FIFO 로 대체하고 사유별로 센다.
- **API 키:** `ANTHROPIC_ASEL_API_KEY` 를 클라이언트 생성 시에만 읽는다. 프로세스 환경에 없으면 Windows 사용자 환경변수에서 읽는다.
  로그·manifest·캐시·사용량에 기록하지 않음 (테스트로 확인).

## 대안 포기 비용

- 더 강한 모델의 결정 품질 이득을 측정하지 못할 수 있다 → Sonnet 팔로 일부 보완.

## 위험

- 가격 표는 캐시된 값이다. 실제 청구와 다를 수 있다 → 가드는 과대 추정 쪽으로 설계했고, 실제 사용량은 콘솔에서 대조 필요.
- 캐시된 응답은 그 시점 모델 버전의 출력이다. 모델이 바뀌면 재현과 재측정을 구분해 보고해야 한다.
- 관측 JSON 이 커지면(대기 작업 누적) 입력 토큰과 비용이 늘어난다. 관측 크기 제한은 정책 간 정보 공정성과 얽혀 있어
  여기서 정하지 않고 EXP-001 파일럿에서 실제 크기를 측정한 뒤 정한다 (코드 리뷰 지적, 보류).

## 검증

- `tests/test_claude_policy.py`: 기본 replay·키 불필요, 기록→재생 바이트 동일, 무효 제안 거절, 프롬프트에 숨겨진 값 없음,
  예산 상한·호출 상한, API 오류·거절·형식 오류 대체, API 키 미기록, 가격 계산, manifest 사용량 기록.
- 모든 테스트는 가짜 클라이언트를 쓴다. 실제 API 호출은 EXP-001 승인 후 #13 에서만.

## 재검토 조건

- EXP-001 승인 시 모델 팔 구성이 바뀔 때
- 파일럿 비용이 추정 범위를 벗어날 때
- 가격 표가 갱신될 때

## 사후 기록 (2026-11-11, EXP-003)

- **위 원칙("상한이지 소진 목표가 아니다")을 어겼다.** EXP-003 표본 크기 규칙(계획서 §3.4)을 "남은 예산을 우선순위대로 최대한 채운다"로
  설계해, 본 실행 약 3시간 45분 동안 장부가 $10.67 → $45.49 로 늘었다. 사용자는 크레딧을 만료일까지 나눠 쓸 계획이었고 실행 중 중단을 지시했다
  ([EXP-003 보고서 §8](../../experiments/reports/EXP-003.md)).
- 예산 가드 자체는 설계대로 작동했다(상한 초과 0, 예산 부족 대체 0). 문제는 가드가 아니라 **배분 규칙과 승인 절차**였다.
- **추가 규칙:** 유료 실행 전 팔별 "실행 수 × 실행당 금액" 표를 보여주고 사용자 승인을 받는다. 남은 예산을 다 채우는 표본 규칙을 쓰지 않고
  여러 날 배분을 먼저 묻는다. 탐색 실행도 따로 승인받는다. 사건마다 호출하는 정책은 호출 빈도 제한을 먼저 검토한다.
